Health Check — Three Scenarios

System is ready to accept requests after startup
WhenI request the health check
Thenthe response status should be 200
Andthe response body should indicate the service is healthy
Body asserted: exact shape { "status": "ok" } — not just key presence.
Core liveness contract. An orchestrator expecting 200 with a machine-readable body gets exactly that. If either fails, traffic stops routing to this instance.
Health check response is machine-parseable
WhenI request the health check
Thenthe response content type should be JSON
Header asserted: Content-Type contains application/json.
A client that calls response.json() without checking the content type will throw a parse error if the handler switches from res.json() to res.send(). This scenario pins the wire format independently of the body check above.
Health check endpoint is read-only
Belt-and-suspenders regression guard
WhenI send a POST request to the health check endpoint
Thenthe response status should be 404
No application code runs — 404 is returned by Express routing before the handler is reached.
If a future change accidentally registers a POST /health handler (say, a copy-paste error wiring an admin endpoint), this test fails immediately. Zero src/ lines execute when POST /health arrives today — the 404 comes from Express's routing fallthrough.
Why 404 and not 405 Method Not Allowed?

Express does not automatically return 405 when a route exists but the method doesn't. GET /health is registered; POST /health has no registration — it falls through all routes and reaches Express's built-in 404 handler. A 405 would require explicit middleware that this service does not include.

Glossary
Liveness contract
The binding agreement between the service and its orchestrator: "if I'm alive, GET /health returns 200."
Belt-and-suspenders
A test that guards against a future regression rather than an existing bug. The behavior it tests is already correct; the scenario fails if someone accidentally breaks it.
Wire format
The concrete encoding (application/json) that the caller uses to interpret the response bytes.
