Operations

GET /api/subscribers — List all subscribers 4 scenarios
Reads all registered subscribers from the database and returns them sorted by ID.

Happy path: subscribers returned in registration order; empty list when none registered.

Infrastructure: DB failure returns 500 whether or not subscribers are seeded (belt-and-suspenders).

State integration: a deleted subscriber no longer appears in the list.

No authentication, no feature flags, no configuration dimensions.

POST /api/subscribers — Register a subscriber ~44 scenarios
Creates a new subscriber record, then fire-and-forgets a Kafka topic subscription (no-op in tests).

Happy path: basic HTTPS; HTTP endpoint; custom delivery headers; multiple headers; empty-value header; URL with query string / fragment / credentials / non-standard port / IPv4 / uppercase protocol.

Duplicate: registering identical data twice creates two independent entries — no deduplication.

Validation:

  • Required fields (name, topic, url): missing → 400 Outline ×3
  • Same fields as empty string → 400 Outline ×3
  • Same fields as explicit null → 400 Outline ×3
  • Whitespace-only name / topic → permissive: accepted as-is
  • Whitespace-only url → 400 (fails URL parse)
  • Non-HTTP/HTTPS URL protocols: ftp://, javascript:, data:, file://, https:// (empty host) → 400
  • Malformed JSON body → 400 from Express body-parser (handler never runs)

Injection / special characters Outline ×4: SQL-special chars, XSS payloads, path-traversal, stored and returned literally.

Size: 500-char name; 500-char topic — both accepted (no app-level column guard).

Unknown fields: extra body properties silently ignored.

Infrastructure: DB failure → 500.

DELETE /api/subscribers/:id — Remove a subscriber ~13 scenarios
Deletes the subscriber with the given integer ID. Returns 204 on success, 404 if not found, 400 if the ID is not parseable as an integer.

Happy path: existing subscriber deleted (204).

Not found: non-existent ID → 404.

ID parsing edge cases (all non-existent after parse, so 404 unless stated):

  • "1.5" → parseInt truncates to 1 → 404
  • 0, -1, 9999999 → valid integers, no matching row → 404
  • "007" → parses to 7 → 404
  • "0x5" → parseInt stops at x, yields 0 → 404
  • "Infinity" → parseInt yields NaN → 400 (invalid)
  • "not-a-number" → NaN → 400 (invalid)

Infrastructure: DB failure → 500 (existing subscriber seeded or not — belt-and-suspenders).

What is not tested here

Authentication (none exists in this API), feature flags (none in subscriber routes), environment regions (single-environment deployment), pagination (none implemented), the outbound Kafka subscription side-effect (no-op in tests — covered by the Kafka flow).
